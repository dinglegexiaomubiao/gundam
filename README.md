# 高达 G 世纪永恒 资料库

个人游戏资料库：抓取 [soshage.com/gget](https://soshage.com/gget/) 的数据（仅 zh-CN 语言），
用于机体 / 驾驶员 / 支援角色配对与伤害计算。

## 数据来源

- 站点自带 JSON API：`https://soshage.com/ggetapi/zh-CN/...`
- 覆盖：机体（1210）、驾驶员（568）、支援角色（84）、系列（108）、
  主线关卡（476）、剧情事件（14，含 78 个 Boss 关卡）、塔楼（4，40 层）。
- 敌人数据在关卡详情 `stage/{id}` 的 `map.npcs` 中（敌方机体 + 敌方驾驶员实例数值）。

## 目录结构

```
data/
  raw/zh-CN/           原始 JSON（抓取产物，不提交 git）
    unit/{id}.json     机体详情
    character.json     驾驶员全量
    supporter.json     支援角色全量
    stage/{id}.json    关卡详情（含敌人）
    event/...          剧情 / 塔楼事件
  db/gundam.db         SQLite 规范化数据库
  meta/manifest.json   抓取元信息
src/                   代码库（API 客户端、抓取、入库、校验）
scripts/pipeline.py    命令行入口
```

## 使用

```powershell
python scripts/pipeline.py fetch          # 全量抓取（断点续传）
python scripts/pipeline.py fetch --limit 10   # 冒烟测试：每类详情只抓 10 条
python scripts/pipeline.py build          # 原始 JSON -> SQLite
python scripts/pipeline.py verify         # 数量与抽样校验
python scripts/pipeline.py all            # fetch + build + verify
python scripts/pipeline.py restore        # 从云端 PostgreSQL 恢复本地数据库
python scripts/pipeline.py serve --port 8765   # 启动本地 Web 查看器
```

启动后浏览器打开 <http://127.0.0.1:8765>，可浏览机体 / 驾驶员 / 支援角色 / 关卡敌人，
并使用伤害计算器（公式来自 formulas.docx）。

## 云端数据库与启动兜底

本地数据库（`data/db/gundam.db`）不进 git，新 clone 后没有数据。启动时按以下顺序兜底：

1. **本地已有数据库**：直接使用；
2. **本地缺失**：尝试从云端 PostgreSQL（Neon）恢复——设置环境变量
   `NEON_DB_URL`（例如 `postgresql://user:pass@host/db?sslmode=require`），
   执行 `python scripts/pipeline.py restore` 或直接 `serve`（自动恢复）；
   批量读取会自动走 Neon 直连端点（比池化快），带逐表 180 秒硬超时与最多 3 轮断点续传重试；
3. **云端也没有/不可用**：不自动爬取，直接在空库状态下启动，可在概览页
   「导入数据库」恢复，或点击「爬取数据」按钮手动全量抓取。

```powershell
$env:NEON_DB_URL = "postgresql://user:pass@host/db?sslmode=require"
python scripts/pipeline.py serve          # 本地无库时自动：云端恢复 -> 失败则空库启动
```

向云端上传本地数据使用迁移脚本（同样依赖 `NEON_DB_URL`）：

```powershell
python scripts/migrate_cloud.py           # 重建云端表结构并上传全部数据
```

## 导入 / 导出（概览页）

概览页「数据概览」提供两个按钮：

- **导出数据库**：下载当前本地 `gundam.db`（SQLite 文件，可直接再导入）；
- **导入数据库**：选择一个导出的 `.db` 文件，校验通过后自动替换本地数据库
  （保存到 `data/db/gundam.db`，重启后依然有效）。本地已有数据时会先确认是否覆盖。
- **爬取数据**：仅手动触发，点击并确认后才会全量抓取并构建数据库（不会自动爬取）。
- **上传本地到服务器**：以本地数据为准，在云端重建全部表并覆盖（整体重建，不产生重复数据）。
- **服务器同步到本地**：以云端数据为准，重建本地数据库。

两个同步按钮点击后会先对比本地与云端：逐表列出行数差异、构建时间与本地完整性
（`PRAGMA quick_check`）。若两边不一致，会提示差异在哪，并由你选择「以本地为准
（覆盖服务器）」或「以服务器为准（覆盖本地）」；一致时无需同步。同步期间
导入 / 导出 / 爬取按钮会禁用，防止并发写库。

本地没有数据库时也能启动 Web，在概览页直接导入数据或手动点击「爬取数据」，
不必先连接云端。

## 配对功能

配对页支持两个方向：
- 机体 → 驾驶员 / 支援：输入机体，推荐最契合的驾驶员与支援角色；
- 驾驶员 → 机体：输入驾驶员，推荐最契合的机体。

评分模型（满分 100）：
- 属性契合 30 分：驾驶员射击/格斗/觉醒属性与机体武器属性（攻击属性 1=射击、2=格斗、3=觉醒）匹配度；
- 驾驶员加成 50 分：技能（0.7 权重）/能力（1.0 权重）中可作用于该机体的伤害与属性加成，
  含系列/标签条件（如"搭乘单位含地球联邦军标签时伤害+15%"）；
- 同系列 +6 分：驾驶员与机体同属一个系列；
- 支援加成 20 分：支援队长技对该机体系列/标签条件的加成。

## 属性与星级计算

机体与驾驶员的属性展示遵循以下规则：

- **类型**：机体与驾驶员均分三大类，`role` 字段 1=攻击型、2=耐久型、3=支援型
  （依据角色/机体的属性分布推断，列表与详情均显示）。
- **多系列归属**：机体/驾驶员可同时属于多个系列（`series_set`），系列筛选按全量匹配，
  支援角色词条中的系列条件可直接搜到该系列全部机体/驾驶员。
- **筛选交集/并集**：机体/驾驶员搜索的系列、类型、标签三个维度可组合为
  「交集（全部满足）」或「并集（任一满足）」（`match=and/or`，标签内部另有全部/任一）；
  支援角色详情的「显示所有影响对象」即其全部词条条件（系列 ∪ 标签）的并集搜索。
- **机体星级倍率**：只有机体有星级（0/1/2/3 四档），驾驶员没有星级；
  0→1 星提升 20%（×1.2），1→2 星提升 30%（×1.3），2→3 星提升 40%（×1.4）。
  机体作用于 HP、EN、攻击力、防御力、机动力；驾驶员作用于射击、格斗、防御、反应、觉醒。
- **机体/驾驶员等级上限**：UR=100、SSR=90、SR=80、R=70、N=60；
  非 UR 机体需 SP 才能升到满级 100，另有 SSP（以 SP 为前提）直接显示最终属性；
  当前数据未收录 SSP 属性时，SSP 形态暂按 SP 数值显示并提示。
- **终极标签机体**：带「终极」标签的机体暂时不能 SP、不能升星，
  统计与显示一律使用无 SP、0 星的数据（列表、详情、排序均如此）。
- **升星公式**：`星级基础值 = floor(基础值 × 倍率)`；
  `最终值 = floor(星级基础值 × (1 + 能力加成%))`；
  界面上的绿色 `+N` 即能力加成部分（`最终值 − 星级基础值`）。
- **驾驶员等级上限**：UR=100、SSR=90、SR=80、R=70、N=60（默认满级属性即数据中的 `max_*`）；
  非 UR 驾驶员可在详情中点「SP 解锁满级 100」，显示 SP 形态（`sp_*` / `sp_max_*`）的 100 级属性。
- **无条件能力加成**（如"最大HP提升15%"）直接并入属性显示；
  有条件的能力加成（需达成标签/系列/HP/战意等条件）可在属性栏点击「查看条件加成」查看达成后的数值。
- **武器等级**：所有武器直接显示最高级（普通武器 LV5，SSP 武器特效到 LV9）；
  属性取属性成长最高档（1~5 级）修正值（威力/EN/命中/暴击 = floor(基础值 × 修正率 / 100)），
  特效取最高级对应槽位的特效名 + 完整效果文本。

公式同时记录在数据库 `meta` 表（`star_multipliers` / `star_labels` / `star_formula`）。
